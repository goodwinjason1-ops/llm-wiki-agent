# Karpathy Self-Learning Lessons Review and Implementation Workflow

## Purpose

Turn lessons generated by the Karpathy/self-evolving vault loop into useful changes without blindly editing the vault.

The loop should produce suggestions. Ari/Claude/Jayse then review, approve, implement, verify, and log the best ones.

## Source of lessons

Primary inputs:

- [[Connection Illumination Dashboard]]
- `04_Wiki/queries/Missed Connections Review - YYYY-MM-DD.md`
- [[Karpathy Connection Synthesis - 2026-07-08]] and future synthesis pages
- `00_System/Reports/Vault Loop Report - YYYY-MM-DD.md`
- [[AI Second Brain Dashboard]] pinned docs and scheduled-loop sections

## Review cadence

| Cadence | Owner | Action |
|---|---|---|
| Daily / 6:20am | script-only loop | Generate deterministic reports, dashboards, lint findings, and suggestions. |
| Weekly | Ari/Hermes | Summarize top suggestions and propose 3-5 implementation candidates. |
| Deep implementation session | Claude Code / Ari | Apply approved changes, verify, update dashboards/index/log. |
| Human steering | Jayse | Approve high-impact changes, reject noise, set priorities. |

## Lesson intake schema

Each candidate lesson should be reduced to one row/card with:

```text
lesson_id:
source_report:
lesson_type: missing-link | orphan | dashboard-gap | workflow-upgrade | project-next-action | cleanup | skill-candidate
summary:
why_it_matters:
affected_files:
expected_benefit:
risk_level: low | medium | high
recommended_action:
approval_needed: yes | no
status: proposed | approved | implemented | rejected | parked
verification:
```

## Triage filter

Only implement suggestions that pass at least one of these tests:

1. **Findability:** will it make a useful document easier to rediscover?
2. **Actionability:** does it create a clear next step for a real project?
3. **Compounding:** will it improve future Ari/Claude runs, not just one note?
4. **Client/product value:** does it strengthen BuyerProof AU, Business Context Brain, Quant Floor, game dev, or another active priority?
5. **Risk reduction:** does it reduce confusion, broken links, stale assumptions, duplicate work, or context loss?

Reject or park if:

- the link is only a keyword coincidence;
- it touches raw sources unnecessarily;
- it creates too many low-value links;
- it would change trading/DeFi/security behavior without explicit approval;
- it is a broad rewrite rather than a targeted improvement.

## Implementation lanes

### Lane 1 — Simple links

Use when the relationship is obvious.

Example: a source summary and its human-readable concept page refer to the same video/article.

Action:

- Add 1-3 direct wikilinks.
- Avoid mass-linking.
- Update `log.md` if the change is durable.

### Lane 2 — Synthesis page

Use when the connection needs explanation.

Action:

- Create a query/synthesis page in `04_Wiki/queries/`.
- Explain why the connection matters.
- Add top next actions.
- Link it from relevant project dashboards.

### Lane 3 — Dashboard/navigation upgrade

Use when several useful notes are hard to find.

Action:

- Add a dashboard section, pinned-doc entry, or project navigation table.
- Prefer one clean hub over many scattered links.
- Update `index.md` if it becomes a durable navigation surface.

### Lane 4 — Workflow upgrade

Use when the lesson teaches a repeatable procedure.

Action:

- Create/update a workflow under `00_System/Workflows/`.
- Add trigger conditions, steps, pitfalls, and verification.
- Pin it if it will be frequently reused.

### Lane 5 — Skill candidate

Use when Ari/Claude should auto-load a procedure in future sessions.

Action:

- First draft as an Obsidian workflow or `08_Skills/` candidate.
- Promote to Hermes/Claude skill only after the workflow has been used successfully.

## Approval rules

Ari can implement without extra approval:

- low-risk wikilinks;
- dashboard navigation additions;
- workflow notes;
- index/log updates;
- report/synthesis pages.

Ask Jayse first for:

- deleting/archiving many notes;
- large rewrites;
- changing cron behavior;
- changing cloud/VPS/security setup;
- anything involving live trading, wallets, API keys, broker/exchange auth, or public network exposure.

## Verification checklist

After implementation:

- [ ] Run or inspect `connection_illuminator.py` if the change affects links/navigation.
- [ ] Run `vault_lint.py` for broken links/frontmatter regressions.
- [ ] Update `index.md` for durable pages.
- [ ] Update `log.md` with files changed and why.
- [ ] If useful for future sessions, add the document to [[AI Second Brain Dashboard]] pinned docs.

## Recommended weekly review format

```text
Karpathy self-learning review

1. New signal summary
2. Top 5 candidate lessons
3. Recommended to implement now
4. Park/reject list and why
5. Files to update
6. Verification plan
7. Questions for Jayse, if any
```
